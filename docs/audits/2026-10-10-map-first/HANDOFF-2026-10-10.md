## How to integrate (what worked, and the traps)

1. **Merge with `--no-ff`** into `feat/map-first`, one branch at a time, newest-contract first. Pin first: `git update-ref refs/safety/<name> HEAD`.
2. **Expected conflicts every time:** `apps/web/src/routeTree.gen.ts` (take either side, then rebuild so the generator rewrites it), `apps/web/src/map/lenses/registry.ts` (keep both lens id lists and both `case` arms), `docs/ARCHITECTURE.md` §7 (keep both blocks), `packages/player-core/src/index.ts` export lines, `scripts/capability-ledger.json` enumerators, `scripts/pin-ledger.json` (keep this side's `ownerApproved` flags; drop rows a branch resolved), and the route placeholders `world.index.tsx`, `washington.index.tsx` (take the real screen, not the "ModeRoot" placeholder).
3. **After a merge, rebuild before judging errors.** `apps/web` reads `packages/*/dist`, so a stale `dist` produces dozens of "no exported member" errors that are not real. Run `find . -name tsconfig.tsbuildinfo -not -path '*/node_modules/*' -not -path './.claude/*' -delete; pnpm run build; pnpm --filter @admin/web run build; pnpm run typecheck; pnpm run lint`. Build must come before typecheck (CLAUDE.md).
4. **Name collisions in the player-core barrel** (`export *` from many modules) surface at typecheck; W6b/W5c both exported `cell`. Rename the internal helper rather than aliasing.
5. **Close each wave in order** with `gates/wN.md` (what was actually run, with counts), the `docs/PLAN.md` row, `docs/BACKLOG.md` (move items to `## Closed` with commit and proof; open what the wave found), `scripts/pin-ledger.json` `currentWave`, and `plan.md` (gitignored; `verify-wave-closeout` reads it). The closeout gate reads the word "landed" in the PLAN status as closed, so a wave that is not closed must not say "landed".
6. **Run the unit suite and Playwright serially.** Parallel load makes simulation-heavy tests cross their timeouts (player-core now has a 20 s budget in `packages/player-core/vitest.config.ts`). Use `E2E_PORT=<free port> pnpm --filter @admin/web run test:e2e`. A full Playwright run takes 5–9 minutes; run it in the background.
7. **The git index is shared by every session in this tree.** Agents must use plain `mv`/`rm`, never `git mv`/`git rm`/`git add`, and must not commit in the main tree. Integrate with `git commit -o <paths>`. An earlier leak is recorded in memory (`shared-index-agents-stage-into-commits`). Never `git add -A` and never `git stash` in this repo.
8. **Agents given isolation start on an old base commit.** Brief them to `git checkout -B <branch> <commit>` first. Agent types without a shell (`design`) cannot do build work; use `engineer`.

## If the direction changes

What is load-bearing (changing it costs weeks):

- The engine (`packages/engine`), the world dataset (`packages/world`, including `packages/world/sources/` provenance), the content pipeline (`packages/content`, `studio-cli`), save versions (now v56; `SUPPORTED_SCHEMA_VERSIONS` 51–56), and the proof gates. None of these depends on the map or on any screen.
- `packages/player-core`: presentation-independent selectors, the campaign store, navigation (`navigation/places.ts`), the glossary, force placement, `placeOf`. Screens read these; a new screen design reuses them.
- The contracts between the shell and the map: `useMapDirective` / `MapLayer` / `MapDataProvider` in `apps/web/src/map/directive.tsx`, `data-context.tsx`, `MapLayer.tsx`. A screen declares camera, lens, selection, marks and pins; only the map reads them.
- `scripts/capability-ledger.json` and `verify-engine-reachability`: every engine act is a row with a due wave. It is how the program proves the new player did not lose a capability. It survives any redesign; only the due waves and the screen file names it reads need updating.

What is cheap to replace:

- Tokens and primitives (`packages/design`, `packages/ui-web`), which are shared implementation, not precedent. The ramps were already rebuilt once (W5 polish). `DESIGN.md` §3 holds the values and `color.test.ts` holds the contrast rules, so a palette change is a token edit plus the test.
- Individual screens under `apps/web/src/{nation,washington,world,record}`. Each is built from selectors plus `Screen`, `CompareAuthorize` and `Receipt`. A different layout means new components over the same selectors.
- Wave order and grouping. `PROGRAM.md` says the plan is input, not law: re-cut waves when they block the outcome, but keep the gate record per wave, the pin ledger and the doc-sync contract.
- The map's lens set and camera keys. They are registries (`apps/web/src/map/lenses/registry.ts`, `camera-keys.ts`); unknown ids fall back to neutral, so adding, renaming or dropping lenses does not break screens.

If the change touches the **map decision** itself, the spike's evidence and the fallback are in `spike-w1.md` and `PROGRAM.md` ("Load-bearing choices"): the fallback is a declared degraded camera contract (pre-baked plates with an affine camera), which the directive contract would still serve.

If the change touches **platform or delivery** (the player is a browser-first web app; Electron packages the same build for Steam), the standing rule is `DECISIONS.md` §8: `apps/web` must not import `react-native`, `expo` or React Native Web (`verify-web-boundary`). The desktop host needs `apps/web/dist/index.html` at the root, no inline scripts, and a web build before packaging.

When updating a document for a changed direction, update `docs/DESIGN.md`, `docs/PLAN.md` and the program file in the same commit as the work, and add a decision to `docs/DECISIONS.md` if a standing rule changes. Do not cite deleted records; `verify-no-history-references` fails on the earlier nation's name, decision-record numbers and removed paths.

## Standing rules that bite

- American English and US units everywhere (`verify-american-spelling`, `verify-us-units`).
- No code comment cites a backlog, decision or tracker id; say the reason inline. Why-comments only.
- Never state a number, path or command you have not observed; verify before claiming done. Run the project's real validation path, not a smaller one.
- No Co-Authored-By or AI-product trailers in commits. Commit unsigned: `git -c commit.gpgsign=false commit`.
- Secrets come from 1Password through the existing launchers; never print values. Never put the owner's email or any personal identifier into an outbound request (a generic User-Agent only). One Wikipedia request in W1 carried the email in its header by mistake, once; every later request was generic.
- Draw readings as gauges, meters and series, not label-and-word tiles. Portraits are editorial, never cartoon, and never show hidden stats.
- Ask the owner with named options and real costs, never open-ended (`AskUserQuestion`).
- Cost discipline: Opus for engine, integration and review, Sonnet for scoped screens and data, Haiku for chores. Do not fan out beyond the need; the owner approved this program's parallel worktree agents explicitly.
