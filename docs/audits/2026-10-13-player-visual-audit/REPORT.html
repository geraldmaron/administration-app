01 · Refine the existing system

The Administration · visual audit · October 13, 2026

Player visual audit — modern presidential workspace

Refine the existing system. Correct misleading visual semantics and missing subject links first; then establish a clearer surface hierarchy and compose each screen around the situation, its evidence, and the next useful action.

Scope delivered: evidence, priorities, annotated direction and an implementation specification. No application redesign or simulation change was made.

Fix meaning first

A price rise can currently display a down arrow. Page-map preferences have a source-confirmed propagation gap. Cosmetic work must not conceal those defects.

Keep what works

Semantic icons, persisted portraits, formal documents, maps, chart primitives and real subject routes already exist. The navigation crawler followed 139 doors without a detected failure.

Be precise about wrapping

The tested desktop surfaces fit. A broad large-screen wrapping defect was not reproduced. Fixed content measure and nested layout remain relevant constraints, not proof of a bug.

Base commit: 011d0c042fbb2e4e1bbb52c7b5b7b3d17e165fbb. Isolated worktree and local server; fixture saves imported through the player into disposable Chromium profiles. This is a sampled visual audit, not certification of every conditional state.

05 · Direction A · Brief

  1. Priority matter: retain the existing decision and consequence-of-waiting content. Give this panel the strongest hierarchy; avoid a field of equally urgent tiles.
  2. Supporting context: show the actual linked subject identity when available. Use a flag, persisted portrait or relevant map only if it helps identify who or where.
  3. National condition: retain compact comparable readings and signed changes. Link each to its owning analytical surface and the recent causal record.
  4. Continuity: the route from matter to decision to review to result must retain its subject and provide a clear way back. Motion should preserve orientation, with reduced-motion parity.

09 · Implementation sequence and acceptance

  1. Meaning: fix direction/valence and page-map preference propagation.
  2. Shared foundations: refine existing token roles, measured layouts, Series context and endpoint geometry. Keep API changes additive.
  3. Four representative surfaces: Brief, Markets, Security and an office dossier, including their real linked journeys.
  4. Remaining families: extend the same rules without replacing successful compositions. Include entry, help, failure, review and recovery states.
  5. Integration: run required build-before-typecheck validation, real browser journeys, all six sizes and both themes. Inspect long-page tails and nested scroll containers.

Presentation interface changes

CommodityRow gains numeric-derived changeDirection. Series gains optional timeRange, unitLabel and visible-domain support. WorkSurface gains an optional data measure. Markets search gains validated sort/direction while measure preserves subject selection. Maps reuse existing device settings. No engine/save migration.

What finished must demonstrate

Readable numbers and units; no hidden overflow; color-independent meaning; known versus unknown evidence; keyboard and focus restoration; theme and preference consistency; supplier/subject Back behavior; explicit cancel, stale-data, refusal and persistence-error paths.
